# Traceability Rules

## Mandatory rules
- Every requirement or backlog item must have a source or objective anchor.
- Every feature, epic, story, use case, and task should map to the relevant parent artifact.
- Confirmed decisions and assumptions must be explicitly tracked.
- Changes to scope should trigger impact review and update of dependent artifacts.

## Recommended linking pattern
Objective -> feature -> epic or story -> acceptance criterion -> validation evidence -> implementation task

## Red flags
- orphan requirement with no objective link
- multiple copies of the same requirement in different files without a synchronization rule
- acceptance criterion not connected to a concrete user or system outcome
