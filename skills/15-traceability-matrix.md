# Skill: Requirements Traceability and Matrix Generation

## Purpose
Show how each business objective, requirement, story, use case, and task relate to one another.

## Input
- backlog and requirement inventory
- objective statements
- validation and acceptance criteria

## Output
- traceability matrix
- source-to-requirement-to-delivery mapping
- gaps, duplicates, and orphan items report

## Execution steps
1. Define objective-level anchors.
2. Link each requirement, story, and use case to one or more objectives.
3. Record validation evidence and completion status.
4. Identify orphan or duplicated items.
5. Update the matrix when scope changes.

## Rules
- Traceability should support accountability, not create redundant copies of the same fact.
- Link to the source artifact, not just a title.

## Validation checks
- Every requirement has an owner and source.
- Each requirement traces to an objective or accepted need.
- Coverage gaps are explicit and reviewed.
