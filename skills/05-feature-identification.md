# Skill: Feature Identification and Decomposition

## Purpose
Identify cohesive capability groupings that deliver stakeholder value and support prioritization.

## Input
- clarified requirements
- business objectives and scope statements
- candidate user flows or process notes

## Output
- feature catalogue
- feature descriptions
- value statement and stakeholders
- links to related requirements and backlog items

## Execution steps
1. Group related requirements by customer or business outcome.
2. Confirm the grouping is cohesive and valuable.
3. Check whether the feature is meaningful at the solution/component level.
4. Decompose only when needed, preserving a single parent relationship.
5. Prioritize and sequence features by value and uncertainty.

## Decision rules
- Feature is not a loose list of tasks or technical components.
- Feature should correspond to a meaningful solution capability or set of requirements.
- Feature decomposition should stop at just enough detail for the next decision.

## Validation checks
- Does the feature map to stakeholder value?
- Are child features meaningful, not just implementation steps?
- Does the feature remain coherent after decomposition?
