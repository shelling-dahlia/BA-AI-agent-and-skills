# Skill: User Story Creation and Refinement

## Purpose
Write small, valuable, testable stories that invite conversation and support delivery planning.

## Input
- feature or epic scope
- stakeholder needs
- acceptance criteria candidate notes

## Output
- user story catalogue
- story title and value statement
- acceptance criteria
- priority and readiness notes

## Execution steps
1. Identify the actor, desired behaviour, and value.
2. Write the story in a short narrative form.
3. Ensure the story is independent, valuable, estimable, and testable.
4. Add acceptance criteria and clarify unresolved decisions.
5. Split or refine oversized stories when needed.

## Story patterns
- As a <role>, I need <capability>, so that <value>.
- In order to <value>, as a <role>, I need <behaviour>.

## Rules
- Stories are not a substitute for all analysis detail.
- Acceptance criteria should define boundaries and expected outcomes.
- Do not write a story as a technical implementation step.

## Validation checks
- INVEST quality: independent, negotiable, valuable, estimable, small, testable
- clarity and business value are explicit
- acceptance criteria are testable and objective
