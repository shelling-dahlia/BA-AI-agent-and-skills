# Skill: Acceptance Criteria and Requirement Validation

## Purpose
Define the minimum outcome needed to confirm value is delivered and the requirement is satisfied.

## Input
- user story or use case draft
- rule, constraint, or business outcome

## Output
- acceptance criteria list
- validation checklist
- unresolved assumptions and edge cases

## Execution steps
1. Define the expected condition for success.
2. Capture edge cases and error handling.
3. Use objective, testable, and finite wording.
4. Break large criteria into atomic checks when necessary.
5. Link them to the story or use case they validate.

## Rules
- Acceptance criteria must be verifiable as true or false.
- They should describe boundaries, not full solution architecture.
- They may be written as lists, scenarios, or Given/When/Then statements.

## Validation checks
- Testable and precise?
- Unambiguous for all critical scenarios?
- Linked to a requirement or objective?
