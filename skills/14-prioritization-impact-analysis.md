# Skill: Prioritization and Change-Impact Analysis

## Purpose
Decide what gets delivered first and assess what changes when a requirement changes.

## Input
- backlog items or requirements
- stakeholder priorities
- known constraints and dependencies

## Output
- prioritization scheme
- impact analysis
- affected requirements and stakeholders
- change-risk notes

## Execution steps
1. Determine criteria such as value, urgency, dependency, risk, and effort.
2. Rank candidate items with rationale.
3. Identify downstream impacts of a change.
4. Capture affected stories, screens, use cases, and tasks.
5. Recommend whether to iterate, defer, or replace impacted work.

## Rules
- Prioritization must reflect value and constraints, not only implementation convenience.
- Change impact analysis should track cross-artifact dependencies.

## Validation checks
- Are prioritization criteria explicit?
- Are affected artifacts and consequences documented?
- Is the impact limited to dependencies, not hidden assumptions?
