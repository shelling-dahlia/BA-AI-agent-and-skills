# Skill: Mockup, Screen, and User-Flow Support

## Purpose
Capture user-interaction requirements, screen expectations, and journey-level requirements without prematurely designing the final UI.

## Input
- user journeys or process notes
- design goals or UX sketches
- outputs from stories or use cases

## Output
- screen inventory
- user-flow description
- screen-level requirements
- interaction or validation notes

## Execution steps
1. List the screens or user stages in the journey.
2. Identify the purpose of each screen and the user action it supports.
3. Record required user inputs, validation needs, and state transitions.
4. Note assumptions or missing design decisions.
5. Link each requirement back to the relevant story or use case.

## Rules
- Screen requirements should support the user story or use case, not replace it.
- Wireframe-level detail should not embed business rules that belong elsewhere.

## Validation checks
- Are screen purposes traceable to the goal?
- Is the flow understandable and complete enough for review?
- Are assumptions marked as proposals rather than facts?
