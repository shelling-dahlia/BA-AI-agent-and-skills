# E-commerce Shopper Purchase Backlog

This folder decomposes the provisional **“Shopper purchases a product”** journey from [the initial requirements analysis](../e-commerce-requirements-analysis.md) into candidate epics, features, user stories, acceptance criteria, and delivery tasks.

- [Traceability matrix and open decisions](./traceability.md)

## Scope and status

This is a candidate backlog for client and delivery-team review, not a set of approved requirements. The source journey proposes that the shopper discovers a product, reviews it, adds it to a cart, enters checkout details, selects delivery and payment, submits the order, and receives an outcome.

The source analysis did not include an EPC diagram. These epics and features are therefore derived from the written shopper journey, **not from EPC elements**. Validate them against the client’s EPC and confirm the system boundary before treating them as committed scope.

Business decisions such as guest checkout, payment timing, tax calculation, stock reservation, delivery availability, and order status are not specified. Acceptance criteria use configured or agreed rules where necessary and identify unresolved choices in [the traceability matrix](./traceability.md).

## Identifiers

- Epics: `EP-01` to `EP-03`
- Features: `FEAT-01` to `FEAT-07`
- User stories: `US-01` to `US-13`
- Acceptance criteria: `AC-01` onward
- Tasks: `T-001` onward

Priorities, estimates, owners, and release assignments are intentionally left open pending client and team review.
